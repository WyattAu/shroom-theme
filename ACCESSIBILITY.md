# Accessibility testing

The palette in this theme is designed against measured colour models rather
than by eye, and the measurements are enforced in CI. That covers contrast and
lightness separation. It does not cover whether the theme is actually usable,
which requires people to use it.

What follows is what to test, and what a result means.

## What is already covered

Run `npm run audit:palette`. It gates on:

- **WCAG 2.1 AA (4.5:1)** for every text token, measured on the alpha-composited
  pair, so a translucent token is measured as rendered.
- **WCAG 2.2 SC 1.4.11 (3:1)** for non-text components that carry meaning,
  including `focusBorder`.
- **APCA |Lc| separation of at least 2** between any two competing token
  categories, so no pair differs by hue alone.

See [docs/color-science.md](docs/color-science.md) for what each metric does
and does not guarantee.

## What simulation cannot tell you

The deuteranopia, protanopia and tritanopia variants are generated by simulating
full dichromacy. That is a **worst-case collision detector**, not a picture of
what anyone sees.

Two reasons, both worth internalising before interpreting a preview:

- Only about a quarter of people with colour vision deficiency are dichromats.
  The rest are anomalous trichromats whose impairment is milder, so the variants
  overstate the difficulty for most people who use them.
- Simulated colour does not predict perception. In independent evaluation, only
  one of several popular simulators tracked real dichromats, and results from
  non-CVD users often differed from those produced by CVD users themselves.

If a pair is distinguishable in the variants, it is distinguishable for the
milder anomalous trichromacies too. That is the useful property, and it is the
only one.

## Who to recruit

Aim for **at least one deuteranomalous and one protanomalous** participant. Those
are roughly three quarters of CVD users, and they are exactly the population the
dichromat variants misrepresent. Testing only dichromats validates a worst case
that most users do not experience.

One tritanope would also be valuable: tritanopia is around 0.008% of the
population, so it is almost never represented in casual testing, and it is the
one deficiency where the palette's hue choices are most constrained.

## Tasks to give

Give tasks, not screenshots. A screenshot tests rendering; a task tests whether
the user can work.

1. **Definition or call?** Two functions with the same name, one defined and one
   called. This targets the keyword/variable pair, which sits at APCA |Lc| 54.4
   and 1.5 CIEDE2000 apart under simulated deuteranopia.
2. **Which line has the error?** A short file with one syntax error.
3. **Which line was added, which removed?** This is diff readability, and it is
   the thing users most often ask for CVD support around.
4. **How do you say these colours out loud?** Read a snippet and name the token
   colours aloud. The red/green/brown category mismatch is a distinct failure
   mode that no colour difference metric catches.
5. **Are the comments hard to read?** Comments are held to 3:1 rather than 4.5:1
   in this theme, on the reasoning that they are de-emphasis rather than body
   text. That is a judgement call and it is worth checking with someone who
   actually reads comments.

## Reporting

If someone finds a token pair they cannot tell apart, the useful information is:

- the two colours (or the token kinds)
- the file and line, or a screenshot
- the theme and variant they were using
- whether their viewer settings include a colour filter or reduced transparency,
  which changes the rendered result

Colour difference between two hex values can be computed directly:

```bash
node -e "
const c = require('./color-science.js');
console.log('dE00:', c.deltaE00('#RRGGBB', '#RRGGBB').toFixed(1));
for (const k of ['protan','deutan','tritan'])
  console.log(k, c.deltaE00(c.simulate('#RRGGBB', k), c.simulate('#RRGGBB', k)).toFixed(1));
"
```

A CIEDE2000 below about 10 between two colours that appear in the same line is
a real confusability. Below 2 is functionally identical.
